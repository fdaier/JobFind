# Draft PRD：测评链接与截止时间

> 状态：待用户确认，尚未开始产品实现。  
> 日期：2026-09-14  
> 数据原则：新增字段只补充既有岗位，不改写公司、岗位、JD、材料、时间线、复盘或既有日期。

## 1. 当前缺口

当前岗位只有网申截止时间、笔试时间和面试时间。虽然时间线可以手动添加事件，但它不参与看板的“关键时间”计算，也不会进入 Agent 风险和今日任务。

因此，收到测评链接后，当前没有一个既能记录**测评截止时间**、又能让看板和 Agent 使用的入口。

## 2. 用户流程

收到测评链接后：

1. 打开对应岗位详情，将阶段调整为“测评”（若仍在已投递）。
2. 进入“基本信息”→“编辑”→“关键时间”，填写“测评截止时间”，可选填写测评链接或来源说明。
3. 保存后，看板卡片的关键时间显示最近的“测评截止”；Agent 按剩余时间生成风险和今日任务。

新建岗位时，若当前阶段选择“测评”，导入表单和预览页同样提供“测评截止时间（选填）”。字段始终可编辑，不要求用户重新创建岗位。

## 3. 数据与交互

岗位新增以下可选字段：

- `assessmentDeadline: string | null`：测评可完成的最后时间；与现有日期一样存为 ISO 时间。
- `assessmentLink: string | null`：测评链接，作为用户填写的原始链接，不自动访问、解析或上传给第三方。

已有岗位在读取时补 `null`，不触发阶段迁移、备份重写或演示数据重置。

“基本信息”编辑态新增一个**关键时间**区块：

| 字段 | 用途 |
| --- | --- |
| 网申截止时间 | 已有字段，保持现有年/月/日输入和日历选择 |
| 测评截止时间 | 新字段，支持日期和具体时分；链接常常精确到当天某时 |
| 笔试时间 | 现有数据字段，补足可编辑入口 |
| 面试时间 | 现有数据字段，补足可编辑入口 |
| 测评链接（选填） | 仅用于快速返回测评入口，不自动打开或抓取 |

为避免误把“测评开始时间”当作截止时间，字段标题固定使用“测评截止时间”，卡片显示为“测评截止 9/18 20:00”。卡片仍只展示一个最近且未过期的关键时间；若没有未来节点，沿用当前“已过期／暂无关键时间”规则。

## 4. Agent 风险与提醒语义

新增可解释风险类型 `assessment_deadline`：

| 条件 | 看板 Agent 风险 | 今日任务 |
| --- | --- | --- |
| 已过期 | `测评已截止 X 小时/天`（紧急） | `确认 <公司> <岗位> 测评状态` |
| 剩余 ≤ 24 小时 | `测评剩余 X 小时`（紧急） | `完成 <公司> <岗位> 测评` |
| 剩余 24–72 小时 | `测评剩余 X 天`（高） | `安排完成 <公司> <岗位> 测评` |

风险默认仅在岗位处于“测评”阶段时激活，避免已经通过或放弃测评、但忘记清空旧时间时反复告警。收到链接时应将阶段调整为“测评”；调整阶段控件会保留这一能力。

本期的“提醒”是**站内提醒**：在打开 JobFind 时，风险会出现在看板卡片、今日作战台和 Agent 排序中。当前静态 localStorage 产品没有后台服务，应用关闭时不能主动发送浏览器通知、手机推送、短信或邮件。

若需要真正的系统推送，后续需单独设计 P1：用户授权浏览器通知、定时后台执行/服务器、时区与失败重试，以及多设备数据同步；不应伪装为当前 Agent 已具备的能力。

## 5. 验收与数据保护

1. 旧岗位读取后仍完整，新增两个字段均为 `null`；不修改现有内容。
2. 既有岗位可在基本信息编辑中填写测评截止时间和链接，保存后刷新仍存在。
3. 新建岗位可填写上述字段；预览与最终保存使用同一份用户输入。
4. 卡片正确显示最近的测评截止时间；不显示多个时间造成信息拥挤。
5. Agent 在测评阶段按 72/24 小时及逾期阈值给出正确的风险、任务和排序。
6. 单测、类型检查、lint、构建、本地和生产浏览器回归通过。
