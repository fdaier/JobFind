# Draft PRD：V2 真实 JD 录入与岗位整理

> 状态：草案，待确认后才进入正式 spec、实现和发布。
>
> 日期：2026-09-14
> 关联页面：`/board` → “粘贴 JD 添加岗位”

## 结论

当前入口**不能用于真实岗位录入**。它是一个演示原型：无论用户修改成什么 JD，预览和保存时都会构造同一条“B站 · AI 产品实习生”模拟数据。因此，当前产品可以演示申请看板流程，但不能诚实地称为可用的 JD 解析/岗位添加工具。

本期先把它改为可靠的“岗位录入 + JD 整理”能力，让用户能把真实岗位保存到自己的申请看板；不把本地规则伪装成线上 AI。真正的 LLM 语义解析另列为后续可选项，需用户明确授权模型供应商、费用和密钥托管方式。

## 已确认的问题与代码证据

| 用户看到的问题 | 根因 | 影响 |
| --- | --- | --- |
| 弹窗每次出现 B站 JD | 输入框初始值固定为 `sampleJD` | 用户误以为该内容是当前待编辑岗位或系统已识别到的内容 |
| 改成腾讯 AI 产品经理 JD 后，结果仍是 B站 | 点击“解析 JD”和“保存到看板”均调用 `createParsedJDJob()`，该函数将公司、岗位、DDL、JD、关键词和材料全部硬编码为 B站样例，并未读取输入框内容 | 录入的数据错误，不能用于真实申请跟踪 |
| 只有一个 JD 输入栏 | 产品假设从 JD 首行识别公司和职位；现实中职位名称/公司常在职位页标题，正文并不包含 | 输入方式不符合真实求职场景，且识别无法可靠 |
| 显示“正在识别公司、岗位、DDL” | 当前没有模型、后端或文本解析逻辑；只是 800ms 的模拟加载 | 产品文案造成“已由 AI 解析”的错误预期 |
| 预览不能修正 | 结果页只读 | 即使未来抽取有误，用户也无法在入库前校准 |

相关实现：`src/components/ai/jd-parser-dialog.tsx`、`src/lib/mock-data.ts`、`src/components/ai/jd-parser-result.tsx`。

## 本期目标（P0）

让真实的“公司 + 岗位名称 + JD 正文”进入本地申请看板，并保证：

1. 保存后的公司、岗位名称、完整 JD 必然来自用户的输入，不再出现 B站替换或虚构内容；
2. 截止时间未知时保持“未设置”，绝不自动制造“三天内”的 DDL；
3. 系统可依据 JD 中明确出现的词做**本地规则整理**（关键词、材料建议），且用户能在保存前修改；
4. 添加失败或整理不充分不会阻止用户保存真实岗位；
5. 入库后仍可使用现有的阶段推进、删除、材料绑定和复盘功能。

### 非目标

- 不实现向腾讯/B站/招聘网站自动提交简历。该产品此阶段是“申请管理工具”，不是跨招聘平台的“自动投递机器人”。
- 不在浏览器代码中暴露 API Key，也不宣称接入真实 LLM。
- 不引入登录、数据库或跨设备同步；P0 延续当前浏览器 localStorage 的隐私本地存储模型。

## P0 交互方案

### 1. 更名与空白入口

- 入口改为“导入 JD 添加岗位”（或保留现有按钮文案，但取消“AI 自动识别”的暗示）。
- 弹窗首次打开为**空白表单**，不再预填 B站样例。可另设低强调度“查看示例”帮助理解格式，但点击后才填入，且明确标记为示例。
- 标题下方明确说明：“填写公司、岗位名称和 JD；系统基于文本整理标签和材料建议，保存前请确认。”

### 2. 输入字段

| 字段 | 规则 |
| --- | --- |
| 公司 | 必填，手工输入；例：腾讯 |
| 岗位名称 | 必填，手工输入；例：AI 产品经理 |
| JD 正文 | 必填，保留原文，用于后续查看与规则整理 |
| 申请截止时间 | 选填；为空时入库为“未设置” |
| 当前阶段 | 默认为“待投递”；保存前可选择真实阶段 |

若任一必填字段为空，按钮旁给出具体校验提示，不进入预览。

### 3. “整理并预览”而非伪 AI 解析

提交后在本地立即生成可编辑预览。界面文案使用“根据 JD 整理的建议”，不使用“AI 已识别”。

- 关键词：仅从正文命中的词典中提取（例如 LLM、Agent、RAG、多模态、A/B 测试、用户洞察、增长）；未命中时留空并允许添加。
- 材料建议：根据正文中出现的“简历、作品集、项目、成绩单、证书”等明确要求提出建议；用户可增删勾选。
- 要求摘要：保留 JD 中的职责/要求文本片段或仅显示原 JD，不生成未经验证的概括；用户可编辑。
- 不推断公司、职位或 DDL；这些字段由用户输入为准。
- 预览页面可返回修改；保存后用同一份预览状态创建岗位，而非重新生成模拟对象。

### 4. 入库与反馈

- 使用通用的新岗位 ID，不使用 `bilibili-*` 前缀。
- 时间线写入“添加岗位：腾讯 · AI 产品经理”一类的真实内容。
- 保存成功后打开该岗位详情，并提示“已保存到本浏览器的申请看板”。
- 在岗位详情的基本信息中确认展示原始 JD、真实 DDL（或未设置）和用户确认后的标签/材料。

## 腾讯 AI 产品经理 JD：验收样例

使用本次用户提供的“腾讯 · AI 产品经理”JD 作为自动化和手动验收样例。完成 P0 后：

| 操作 | 预期 |
| --- | --- |
| 填写公司“腾讯”、岗位“AI 产品经理”，粘贴该 JD | 预览与保存均显示“腾讯 · AI 产品经理”，不得出现 B站 |
| JD 含 LLM / MLLM、Agent、RAG、多模态、A/B 测试等 | 整理建议中包含实际命中的相关关键词；允许用户修改 |
| JD 含产品项目、AI 应用原型经验等 | 可建议作品集/项目材料，但用户可取消或补充 |
| 未填写 DDL | 看板和详情不展示虚构日期或“三天内” |
| 保存后刷新页面 | 同一浏览器中岗位、原文 JD 和用户确认的字段仍存在 |

## 技术实现范围

1. 增加独立的 `JDIntakeDraft` / `ParsedJobDraft` 数据结构及本地整理函数；输入、预览和保存共享同一个草稿对象。
2. 移除该用户路径对 `sampleJD` 与 `createParsedJDJob()` 的依赖；样例数据最多只用于显式“查看示例”和测试。
3. 将当前只读 `JDParserResult` 改为可回退、可编辑、可确认的预览。
4. 用真实草稿生成 `Job`：原样保存 `jdText`，正确记录公司/岗位/阶段/DDL，并复用现有 localStorage、看板和风险规则。
5. 更新测试：覆盖空字段校验、腾讯样例的输入→预览→保存、无 DDL、刷新持久化，以及现有删除回归。
6. 验证 `vitest`、`tsc --noEmit`、`eslint src` 与生产构建；确认通过后才进入部署步骤。

## 后续选项（P1）：真正的 LLM JD 解析

若需要模型理解长 JD、抽取隐含要求、生成岗位匹配建议，可增加服务器端 API（Vercel Function 或独立后端）调用用户授权的模型。该版本需要单独确认：模型提供方、预算/限额、密钥托管、隐私告知、失败降级与输出评估集。无论是否接入，手工录入与可编辑预览必须始终可用。
