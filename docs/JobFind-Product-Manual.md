# JobFind 产品使用手册

## 1. 产品一句话

JobFind 是一个面向学生求职场景的 AI 求职项目经理。它不是单纯记录岗位的看板，而是把岗位、时间节点、材料、面试和复盘串成一条推进链路，持续告诉用户“现在最该做什么”。

当前版本为 `v1.2`。它已经具备完整可演示体验，但 Agent 仍是规则型运行时，用于模拟真实 Agent 的判断、记忆和调度能力。

## 2. 这份手册给谁看

这份手册主要给两类人看：

- 面试官：快速理解产品定位、亮点、演示顺序和体验重点
- 试用者：知道从哪里开始、每个页面做什么、如何走完整条求职链路

## 3. 你会在 30 秒内看到什么

进入产品后，用户首先会看到一个不是“空白看板”的首页，而是一个已经带有 Agent 判断的作战台：

- Agent 今日指挥：今天先做什么
- Agent 风险雷达：哪些岗位最容易掉链子
- 阶段看板：申请池整体处于什么阶段
- 转化漏斗：从关注到 offer 的推进情况

这能直接传达产品核心：它不是只帮用户存信息，而是在帮用户推进结果。

## 4. 当前版本的核心亮点

### 4.1 Agent 被放在产品主线里，而不是藏在角落

Agent 能被用户明显感知到，不只存在于一个按钮或一个说明文字里，而是贯穿四个主页面：

- 首页：Agent 今日指挥、风险雷达
- 申请看板：每张岗位卡片直接显示 Agent 风险
- 材料中心：Agent 材料调度，说明当前该补什么、为什么
- 复盘中心：Agent 策略记忆，把渠道、材料、面试沉淀成下一轮动作

### 4.2 产品围绕“求职推进链路”组织，而不是围绕零散功能组织

JobFind 把学生求职中的核心对象接成一条链：

`岗位 -> 时间节点 -> 材料 -> 面试 -> 复盘 -> 下一轮策略`

这意味着用户不需要在多个工具之间来回切换，也不需要自己拼接上下文。

### 4.3 不是做“大而全招聘 CRM”，而是做“学生求职中的下一步判断”

这个产品刻意没有走复杂后台系统路线，而是聚焦学生最真实的几个高频问题：

- 哪些岗位还没投
- 哪些岗位快截止
- 哪些岗位缺材料
- 哪些岗位沉默太久该跟进
- 哪些面试要准备
- 哪些复盘应该沉淀成可复用策略

### 4.4 规则型 Agent 先把体验闭环做出来，为真 Agent 预埋结构

当前版本没有伪装成“已经接了真实大模型”的产品，而是诚实地把规则型 Agent 做成完整体验：

- 有输入：岗位、阶段、DDL、材料、面试记录
- 有判断：风险识别、优先级排序、材料缺口分析
- 有行动：今日任务、阶段推进、补材料、面试准备
- 有沉淀：策略记忆、渠道复盘、复盘中心

这使产品既能演示，又为后续接真实模型 API 留好了扩展空间。

## 5. 页面总览

当前版本共有 4 个核心页面：

1. `/` 今日作战台
2. `/board` 申请看板
3. `/materials` 材料中心
4. `/review` 复盘中心

推荐的演示顺序也是这个顺序，因为它最符合用户真实认知流。

## 6. 快速上手：3 分钟演示路线

如果你是第一次看这个产品，建议按下面顺序体验。

### 第一步：先看首页 `/`

这里先理解产品如何“给判断”。

重点看：

- `Agent 今日指挥`：为什么今天先做这几件事
- `Agent 风险雷达`：为什么这些岗位被标成风险
- `阶段看板`：申请池现在的分布
- `转化漏斗`：整体推进情况

你会立刻感受到产品并不是静态记录工具，而是一个带优先级的求职指挥台。

### 第二步：进入申请看板 `/board`

这里看产品如何把求职推进过程结构化。

重点看：

- 七阶段看板：关注中、待投递、已投递、笔试、面试、录用、已淘汰
- 岗位卡片上的 Agent 风险
- 点击岗位卡片打开详情页

打开详情页后，重点体验：

- Agent 工作区默认在最前
- 岗位时间线
- 材料清单
- AI 建议
- 面试复盘记录
- 阶段推进操作

这是整个产品里最像“求职工作台”的地方。

### 第三步：查看材料中心 `/materials`

这里看产品如何把“材料管理”从附件列表升级成“Agent 调度问题”。

重点看：

- `Agent 材料调度`
- 当前最大缺口是什么
- 哪份材料覆盖岗位最多
- 每份材料的版本、方向、最近更新时间、绑定岗位

这个页面传达的不是“我有多少份材料”，而是“哪份材料对推进结果最重要”。

### 第四步：查看复盘中心 `/review`

这里看产品如何把历史行为转成下一轮策略。

重点看：

- `Agent 策略记忆`
- 渠道复盘
- 面试复盘沉淀
- 转化漏斗

这个页面很关键，因为它让产品从“管理当前申请”升级成“帮用户越投越会投”。

## 7. 每个页面怎么用

## 7.1 今日作战台 `/`

### 作用

让用户一进来就知道今天要先做什么。

### 适合解决的问题

- 今天任务太多，不知道先做哪件
- 哪些岗位最危险
- 当前申请池整体状态如何

### 看什么

- 本周投递数
- 待处理任务数
- 高风险申请数
- 即将面试数
- Agent 今日指挥
- 风险雷达

### 面试官应该关注什么

这里最能体现产品的“判断能力”而非“记录能力”。

## 7.2 申请看板 `/board`

### 作用

把所有岗位按阶段组织起来，并让用户在一个视图中完成查看、推进和补充信息。

### 用户可以做什么

- 浏览不同阶段的岗位
- 查看关键下一时间
- 查看材料完成度
- 查看 Agent 风险
- 点击进入岗位详情
- 从详情里推进阶段
- 添加面试复盘内容
- 通过 JD 粘贴新增岗位

### 面试官应该关注什么

这是产品核心操作区，重点看“岗位详情如何把信息、判断和动作整合在一起”。

## 7.3 材料中心 `/materials`

### 作用

管理材料版本，并把材料与岗位推进关联起来。

### 用户可以看到什么

- Agent 认为当前优先补齐的材料
- 每份材料服务了哪些岗位
- 哪些材料复用价值最高
- 哪些版本是当前有效版本

### 面试官应该关注什么

很多求职产品只做“简历优化”，这个页面展示的是更完整的材料视角：版本、方向、复用、缺口、绑定关系。

## 7.4 复盘中心 `/review`

### 作用

把已发生的申请、渠道表现和面试记录转成可复用策略。

### 用户可以看到什么

- 哪个渠道更值得优先投入
- 面试里哪些问题高频出现
- 哪些经验被沉淀为 Agent 记忆
- 当前转化链路在哪些阶段损耗最大

### 面试官应该关注什么

这个页面体现了产品不只是“帮你管现在”，而是“帮你下一轮更聪明”。

## 8. 推荐演示话术

如果你需要对面试官快速介绍，可以直接使用下面这段话：

> JobFind 不是一个只记录岗位的看板，而是一个学生求职过程中的 AI 项目经理。它会把岗位、时间节点、材料、面试和复盘串起来，持续告诉用户现在最该做什么。我这版先用规则型 Agent 把判断、调度和沉淀的体验闭环做出来，再为后续接入真实模型 API 留好扩展空间。

然后可以继续往下说：

> 我希望面试官看到的不是一堆功能，而是一个完整链路：首页给今天的判断，看板负责推进岗位，材料中心负责补齐关键资产，复盘中心把历史经验沉淀成下一轮策略。

## 9. 推荐演示顺序和讲解重点

### 演示顺序

1. 首页
2. 申请看板
3. 打开岗位详情
4. 材料中心
5. 复盘中心

### 每一步要强调的点

1. 首页：强调 Agent 在指挥，不是静态 dashboard
2. 看板：强调按阶段推进，而不是堆岗位列表
3. 详情：强调判断、信息和动作在同一工作区
4. 材料中心：强调材料是推进资产，不是附件仓库
5. 复盘中心：强调策略沉淀，而不是做完就结束

## 10. 这个产品和普通求职工具有什么不同

普通求职工具往往偏向下面几种：

- 记录岗位的表格
- 跟踪投递状态的看板
- 只做简历优化的 AI 工具
- 只做题库或面试准备的工具

JobFind 试图把这些割裂问题重新组织成一个连续体验，并把 Agent 放到用户真正需要判断的节点上。

它的不同主要在于：

- 它围绕“下一步行动”设计，而不是围绕“信息存储”设计
- 它把材料、时间、风险、面试和复盘连起来了
- 它让 Agent 在多个页面持续出现，而不是只在单点功能里出现
- 它已经为真 Agent 演化留出了接口和结构

## 11. 当前版本的边界说明

为了表达真实和克制，演示时建议把边界讲清楚。

### 当前已经完成

- 完整前端产品体验
- 多页面信息架构
- 规则型 Agent 判断链路
- 岗位详情工作区
- 材料中心
- 复盘中心
- 面试复盘记录
- 基于规则的策略沉淀

### 当前还没有做成最终形态

- 真实大模型 API 接入
- 云端多用户系统
- 持久化后端服务
- 外部招聘平台自动同步
- 真正 autonomous 的 agent loop

### 为什么这样做是合理的

因为当前目标不是做一个重后端平台，而是先把产品判断、信息架构和 Agent 体验做扎实。先把“什么该被自动判断、什么该被沉淀、什么该成为下一步动作”设计清楚，再接入更强能力，产品会更稳。

1. 首页的 Agent 今日指挥
2. 看板卡片上的 Agent 风险
3. 岗位详情里 Agent 工作区默认前置
4. 材料中心里的 Agent 材料调度
5. 复盘中心里的 Agent 策略记忆
6. 产品如何把“岗位 -> 材料 -> 面试 -> 复盘”串成闭环

## 13. 一句话总结

JobFind v1.2 已经不是一个“加了点 AI 文案的求职看板”，而是一个围绕学生求职推进链路设计的 Agent 产品原型。它最重要的价值，不是替用户保存信息，而是持续帮助用户判断优先级、推动动作，并把经验沉淀成下一轮策略。
