# JobFind 163 邮箱状态收件箱设计

> 状态：已确认，待实施
> 日期：2026-09-30

## 目标

让用户授权连接自己的 163 邮箱后，在 JobFind 中发现与既有岗位有关的招聘通知，并以可核查、需确认的状态建议呈现。它不自动投递、不代替用户登录招聘官网，也不静默改变岗位阶段。

## 已确认决策

- 第一优先级是个人 163 邮箱，采用 IMAP 与用户在网易网页端生成的**客户端授权密码**；不使用用户的网页登录密码。
- 引入账号、后端和数据库。Supabase 负责身份认证、Postgres 数据库及行级访问控制；Vercel Node 函数负责 IMAP 同步 API。当前浏览器 localStorage 中的岗位不会被清空或覆写。
- 邮箱授权码只从 HTTPS 连接表单提交到服务端；以 AES-256-GCM 加密后存储，密钥只存在 Vercel 环境变量。浏览器 localStorage、日志、状态建议与错误消息都不得包含授权码。
- 常规识别不使用视觉模型或截图，也不依赖线上 LLM。邮件按主题、发件人、纯文本／HTML 文字、链接和日期进行确定性解析；低置信度邮件只进入待确认列表，不猜测阶段。
- 所有建议均由用户选择“确认更新／保留当前状态／忽略”后才改变看板；录用、淘汰及任何模糊匹配始终需要确认。

## 连接与同步

1. 用户登录 JobFind，打开“状态收件箱 → 连接 163 邮箱”。
2. 页面解释如何在 163 网页端开启 IMAP 并生成客户端授权密码；用户填写邮箱地址和授权密码，服务端立即以 SSL IMAP 测试连接。
3. 成功后只保存加密凭据、邮箱地址的最小必要掩码和 IMAP 游标；不导入通讯录，也不发送邮件。
4. 用户可点击“立即同步”。服务端从上次游标起读取收件箱；首次连接可由用户显式选择“扫描全部历史邮件”。
5. 每封候选招聘邮件生成一条状态建议，原始全文不入库；仅保存发件人、主题、接收时间、受控长度的证据摘要、邮件 Message-ID 哈希、判定规则、置信度与处理结果。
6. 用户随时可以断开连接；断开后立即删除加密凭据和同步游标，并可选择删除已保存的状态建议。

## 状态识别与岗位匹配

### 分类

规则按可解释优先级识别：测评邀请／测评截止、笔试通知、一面／二面／三面／HR 面邀约、录用通知、未通过通知；无法明确归类时标为“需要查看”。提取到的测评或笔试截止日期进入建议卡，确认时才写入岗位关键时间。

### 匹配

将公司正式名与受控别名、岗位名称的高区分度词、投递日期、发件域与邮件日期组合评分：

- 高置信度：公司与岗位均明确命中，或同一岗位有唯一强证据。
- 中置信度：公司或岗位有一项明确命中，显示候选岗位供用户选择。
- 低置信度：不绑定岗位，仅在收件箱显示，不能更新看板。

同一 `Message-ID` 只生成一条建议；用户忽略后保留忽略决定，后续同步不重新打扰。

## 数据与既有岗位

- 建立每位用户的岗位索引（岗位 ID、公司、岗位名、阶段、投递日期、更新时间），用于服务端匹配。首轮只从浏览器**复制**现有岗位索引；不修改、删除或迁移原 localStorage 岗位正文。
- 确认建议时，客户端仍调用现有岗位阶段与时间线更新逻辑，保持现有备份和迁移语义；服务端记录已确认来源，客户端刷新索引。
- 后续跨设备同步需要单独设计，不能借本功能悄然把 localStorage 改成远端唯一事实源。

## 后端约束

- Supabase 表必须启用 RLS，用户只能访问自己的邮箱连接、岗位索引和状态建议。
- IMAP 客户端只在 Vercel Node runtime 运行；使用受维护的 IMAP 库，SSL 校验开启，连接用完即关闭。
- Vercel Hobby 的 Cron 只能每日触发一次，因此第一版以用户触发的“立即同步”为可靠路径；若需要 15 分钟级自动同步，须另行接入已授权的后台调度服务并在上线前明示频率与成本。
- 官网状态不在本期抓取。后续只允许“用户已登录并主动点击”的浏览器扩展读取当前标签页 DOM；默认不使用视觉识别。

## 界面

- 看板控制条新增“状态收件箱”，有未处理建议时显示数量。
- 收件箱首屏先给出连接状态和“立即同步”，不使用营销式横幅。
- 建议列表以来源、时间、建议状态、匹配岗位、置信度和一条简短证据为主；点击后可展开更多摘要及“为什么匹配”。
- 连接状态页只显示掩码邮箱、上次同步、断开与清除数据操作；绝不回显授权码。

## 验收标准

1. 用户可经自己的 163 客户端授权密码完成真实 IMAP 连接，错误时不泄漏秘密。
2. “立即同步”能读取用户主动选择的邮件范围，重复同步不产生重复建议。
3. 真实招聘邮件可被规则归类、匹配或安全地标为需要查看；没有充分证据时绝不改动岗位。
4. 确认建议后，看板阶段／关键时间／时间线正确更新；忽略与保留当前状态不改动岗位。
5. 断开连接会删除服务端凭据；现有 localStorage 岗位在连接、同步和断开全过程均保持不变。
