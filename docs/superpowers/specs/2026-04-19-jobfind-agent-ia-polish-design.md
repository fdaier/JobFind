# JobFind Stage 1.1 Agent IA Polish Design

## 1. Product Principle

JobFind 的核心不是普通岗位管理，而是 `Agent as job-search project manager`。

因此，Agent 不能只存在于底层规则、风险标签或一个排在后面的 tab 里。用户和面试官打开产品时，必须第一时间感知到：

- JobFind 会主动判断当前局势。
- JobFind 会解释为什么现在要做这件事。
- JobFind 会把下一步动作排好优先级。
- JobFind 仍然让用户确认关键动作，而不是擅自执行。

本轮不是新增大功能，而是调整信息架构和表达，让已经完成的 Agent 能力被看见。

## 2. Problem

当前版本已经有较完整的 Agent 输出，但感知仍然偏弱：

1. 岗位详情里 `AI 建议` 位于第 4 个 tab，用户需要主动寻找。
2. 默认打开的是 `基本信息`，强化的是岗位档案感，而不是 Agent 主控感。
3. 首页有 Agent 判断，但它更像任务区的一句说明，没有成为产品主体。
4. 风险雷达、看板风险、关键时间、材料完成度都来自 Agent/规则判断，但文案上更像普通看板字段。
5. `AI 建议` 这个名字偏静态，像辅助提示，不像一个主动管理求职流程的 Agent。

这会导致一个明显风险：

> 我们实际做了 Agent，但面试官/用户第一眼感知不到 Agent。

## 3. Goal

本轮目标是把 Stage 1.1 从“有 Agent 能力”推进到“用户能明确感知这是 Agent 产品”。

成功后用户打开岗位详情时，第一反应应该是：

> 这个产品先告诉我当前岗位该怎么处理，而不是让我自己翻信息。

## 4. Scope

### 4.1 In Scope

- 岗位详情默认打开 Agent tab。
- 将 Agent tab 提到第 1 位。
- 将 `AI 建议` 改名为更主动的 `Agent 作战台`。
- 在 Agent tab 顶部增加轻量岗位摘要，避免用户缺上下文。
- 调整详情页 header 描述，让语气从“先看信息”转为“Agent 先判断”。
- 首页 `今日任务` 区块改名或强化为 `Agent 今日指挥`。
- 风险雷达和看板卡片文案轻量强化 Agent 感知。
- 更新测试，确保 Agent tab 默认可见且第一位。

### 4.2 Out of Scope

- 不做自由聊天 Agent。
- 不接真实模型 API。
- 不做后端。
- 不扩展 Stage 1.2 的完整材料中心、渠道分析或完整复盘系统。
- 不重做整体视觉系统。

## 5. Information Architecture Decision

### 5.1 Tab Order

推荐顺序：

1. `Agent 作战台`
2. `基本信息`
3. `材料`
4. `时间线`
5. `面试复盘`

理由：

- 用户点开岗位详情时，最核心的问题是“现在该做什么”，不是“这个岗位有哪些字段”。
- 公司、岗位、阶段已经在详情页 header 里可见，`基本信息` 不必承担首屏上下文责任。
- `Agent 作战台` 第一位能直接表达产品差异化。
- `材料` 比 `时间线` 更接近下一步动作，因此排在时间线之前。
- `面试复盘` 仍然保留在最后，因为它通常发生在面试后。

### 5.2 Default Tab

打开岗位详情时，默认 tab 从 `基本信息` 改为 `Agent 作战台`。

切换到另一个岗位时，仍然重置到 `Agent 作战台`，让每次查看都先进入 Agent 判断。

### 5.3 Tab Naming

`AI 建议` 改为 `Agent 作战台`。

原因：

- `AI 建议` 听起来像静态提示。
- `Agent 作战台` 更符合“求职项目经理”的定位。
- “作战台”能承接判断、风险、建议、确认动作和展开帮助。

## 6. Detail Sheet Experience

### 6.1 Header Copy

当前描述：

> 先看信息，再看材料和建议，最后再推进下一步。

建议改为：

> Agent 会先判断风险和下一步，你再确认是否推进。

这能直接强化“Agent 先判断，用户再确认”的产品机制。

### 6.2 Agent Tab Top Summary

在 `Agent 作战台` 顶部增加一个轻量岗位摘要，不重复完整基本信息，只服务于上下文：

- 公司 + 岗位 + 当前阶段
- 当前风险摘要
- 当前 Agent 主判断

示例：

> 阿里巴巴 · 产品实习生 · 关注中  
> 当前没有显性风险。Agent 建议先保持关注，五天内完成投递准备。

这个摘要的目标是解决“Agent 第一位会不会缺岗位背景”的疑虑。

### 6.3 Agent Panel Structure

现有结构保留，但展示顺序强调“判断到行动”：

1. 岗位摘要
2. Agent 判断
3. 为什么现在重要
4. 下一步建议
5. 可展开帮助

不新增复杂交互。

## 7. Other Agent Touchpoints

### 7.1 首页

当前 `今日任务` 应强化为 Agent 主入口。

建议改名：

- `Agent 今日指挥`

文案方向：

- 从“只展示最该先处理的前 5 项”改为“Agent 已按风险和时间窗口排好今日优先级”。

保留任务列表，但让用户理解任务不是普通 todo，而是 Agent 排序结果。

### 7.2 风险雷达

风险雷达是 Agent 的感知层，应轻量显性化。

建议标题或说明中加入：

- `Agent 风险雷达`
- `Agent 已识别 DDL、材料、面试和沉默风险`

### 7.3 看板卡片

看板卡片上的风险和关键时间属于 Agent 感知结果。

本轮只做轻量文案强化，不改变卡片结构。例如：

- `风险` 可调整为 `Agent 风险`
- `关键下一时间` 可保留，避免卡片过重

### 7.4 JD 解析

JD 解析是 Agent 的输入入口。

当前文案已经从实现说明改成产品说明，本轮不必扩大，只需保持“保存后进入 Agent 判断”的表达。

## 8. Acceptance Criteria

完成后必须满足：

1. 打开岗位详情默认显示 `Agent 作战台`。
2. `Agent 作战台` 是第一个 tab。
3. `基本信息` 排在第二位。
4. Agent tab 顶部有岗位上下文摘要。
5. 详情页 header 文案明确表达 Agent 先判断、用户再确认。
6. 首页任务区能更明确表达 Agent 排序和今日指挥。
7. 风险雷达或卡片至少有一处轻量强化 Agent 感知。
8. 没有引入自由聊天、真实模型或 Stage 1.2 范围功能。
9. 相关测试覆盖默认 tab、tab 顺序和首页 Agent 表达。

## 9. Testing Strategy

需要更新或新增测试：

- `src/app/board/page.test.tsx`
  - 打开岗位详情后默认选中 `Agent 作战台`。
  - `Agent 作战台` 出现在 tab 列表第一位。
  - `基本信息` 出现在第二位。
  - Agent 面板默认可见。

- `src/components/dashboard/today-tasks.test.tsx`
  - 首页任务区展示 `Agent 今日指挥` 或等价 Agent 主入口文案。

现有全量验证仍然保留：

- `npm run test`
- `npm run typecheck`
- `npm run lint`
- `npm run build`

## 10. Non-Goals

本轮不评价 Agent 输出是否足够聪明，只解决“用户是否明显感知到 Agent 是产品核心”。

后续如果要继续增强，可以进入：

- Agent 对话化
- 模型 API 接入
- 多岗位策略总结
- 投递策略复盘

但这些都不属于本轮。
