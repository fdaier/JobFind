# JobFind 申请看板岗位删除设计

## 决策

申请看板中的岗位可在任意阶段删除，包含“录用”和“已淘汰”。删除是岗位级、不可恢复的本地数据操作，服务于误添加、重复录入和测试数据清理等低频场景。

入口位于岗位详情抽屉底部：使用低强调度的“删除该岗位”文字按钮，与阶段推进操作以分隔线隔开；不在看板卡片、列头或页面主操作区放置常驻垃圾桶。点击后必须经由二次确认。

## 交互

```text
推进阶段
[推进到 …] [标记淘汰]
────────────────────────
[关闭详情]                         删除该岗位
```

确认框标题为“删除「{公司} · {岗位}」？”，说明删除会同时移除申请时间线和面试复盘，并解除材料中的岗位关联，且不可恢复。默认焦点落在“取消”；Escape、遮罩关闭和取消均不改变数据。

确认后，确认框与详情抽屉关闭；对应卡片、列计数与从岗位数据派生的任务、漏斗和复盘统计即时更新。

## 数据规则

Store 提供 `deleteJob(jobId)`，在一次不可变状态更新中：

1. 移除目标岗位；
2. 从每份材料的 `boundJobIds` 移除目标 ID，材料实体仍保留；
3. 若该岗位正在查看，将 `selectedJobId` 清空。

既有持久化 effect 负责将新 `jobs` 和 `materials` 写回 localStorage。时间线、面试复盘、风险与建议均隶属于岗位对象，会随岗位删除。不存在的 ID 不改变状态。

## 边界

本期不做回收站、撤销、批量删除、归档、后端同步或材料实体删除。

## 验收

- 七个阶段的岗位均存在相同删除入口。
- 录用和已淘汰岗位可被删除。
- 删除入口弱于推进和关闭操作，卡片不出现常驻删除图标。
- 取消不改变数据；确认删除会关闭详情并清理岗位、材料关联和持久化数据。
- 测试、类型检查与生产构建通过。
