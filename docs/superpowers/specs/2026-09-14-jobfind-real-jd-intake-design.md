# JobFind 真实 JD 录入设计

## 决策

将申请看板的“粘贴 JD 添加岗位”从固定 B站演示替换为真实的本地岗位录入。用户提供的公司、岗位名称、JD 原文是唯一事实来源；本地规则只能产生可修改的关键词和材料建议，不推断或伪造公司、岗位、DDL。

本期不接入 LLM、后端或自动投递。产品文案称为“整理”而非“AI 解析”，避免将确定性规则冒充为模型能力。

## 视觉与交互原则

- **视觉命题：** 延续看板的克制、信息密集的工作台表面，用清晰字段层级和细分隔线让“录入 → 确认 → 入库”成为平静的单一流程。
- **内容结构：** 输入页只解释范围并收集事实；预览页只展示可核对的事实和建议；页脚只保留返回与保存两个明确动作。
- **交互命题：** 输入到预览使用短暂、克制的整理状态；预览可返回编辑；保存后直接定位新岗位，避免用户猜测是否写入成功。

## 输入页

弹窗标题改为“导入 JD 添加岗位”，说明为“填写公司、岗位名称和 JD；系统基于文本整理标签和材料建议，保存前请确认。”首次打开所有输入项为空。

| 字段 | 控件与规则 |
| --- | --- |
| 公司 | 文本输入，必填 |
| 岗位名称 | 文本输入，必填 |
| JD 正文 | 多行文本，必填，原样保存 |
| 申请截止时间 | `datetime-local`，选填；未填为 `null` |
| 当前阶段 | 选择框，默认“待投递” |

点击“整理并预览”时，字段为空直接展示相应错误，不开始整理。没有预填样例；开发样例不得出现在此用户路径。

## 本地整理与预览

本地整理函数接收完整输入草稿，并返回同一份事实字段与建议：

- 关键词仅来自 JD 明确命中的词典（如 LLM、MLLM、Agent、RAG、多模态、A/B 测试、用户洞察、增长）。
- 材料建议仅对应 JD 明确提及的“简历、作品集/项目、成绩单、证书、求职信”等词；若未提及则保持空列表。
- `requirements` 保存从 JD 中识别到的“岗位要求/任职要求”等段落的有限文本行；未可靠识别时为空，不生成幻想摘要。
- 不自动补充 DDL、材料绑定、联系人、投递日期或招聘来源。

预览将公司、岗位、阶段、DDL 显示为可编辑字段；关键词为可删除标签并可手工添加；材料建议是可勾选的项目。每一次编辑都更新同一个草稿。用户可“返回修改”或“保存到看板”。

## 入库规则

确认保存时，由预览草稿创建新的 `Job`：

1. 使用 `manual-jd-*` 唯一 ID；
2. 原样保存 `company`、`position`、`jdText`，保留用户选定的阶段和 DDL；
3. 初始材料绑定为空，投递日期仅当阶段不是“待投递/关注中”时以当前时间写入；
4. 时间线写入“添加岗位：{公司} · {岗位名称}”；
5. 复用既有 store、localStorage 持久化和确定性风险计算；
6. 保存后选中新岗位并关闭弹窗。

## 边界与失败处理

- 整理函数不调用网络，输入不会离开浏览器。
- 规则未命中不是错误；用户仍可编辑并保存。
- 无 DDL 显示“未设置”，不能出现假日期或“三天内”。
- 本期不做岗位去重、云同步、API Key、LLM、自动申请或招聘网站集成。

## 验收

- 输入“腾讯 / AI 产品经理 / 用户提供的 AI 产品 JD”后，预览、卡片和详情均显示腾讯与 AI 产品经理，不出现 B站。
- JD 原文、空 DDL、阶段、已确认关键词和材料在刷新后仍保存在当前浏览器。
- LLM、Agent、RAG、多模态、A/B 测试等仅在原文含该词时成为建议。
- 必填项校验、返回编辑、保存、删除功能回归均通过自动化测试。
- 类型检查、lint、全量测试和生产构建通过。
