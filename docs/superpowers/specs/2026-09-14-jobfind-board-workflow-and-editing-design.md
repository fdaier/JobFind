# JobFind 看板流程、备注与岗位编辑设计

**日期：** 2026-09-14  
**状态：** 已确认，实施中  
**依据：** `docs/DRAFT-PRD-JobFind-V3-Board-Workflow-and-Editing.md`

## 目标

将申请看板调整为十阶段校招流程，让用户能在详情中维护真实岗位数据，并将看板卡片聚焦在推进所需的时间、风险和备注。产品仍是单浏览器 localStorage 应用；本期不接入自动投递、账号同步或 LLM。

## 体验决策

- 流程为：待投递、已投递、测评、笔试、一面、二面、三面、HR面、录用、已淘汰；“录用”和“已淘汰”是终态。
- 看板继续横向滚动。卡片仅展示关键时间、Agent 风险、20 字以内备注；移除材料完成度与进度条。
- 导入 JD 的基础信息区和预览页都提供同一条备注输入，保存时与公司、岗位和 JD 一同写入新岗位；公司名在卡片中与岗位名使用同级标题层级。
- 详情抽屉中 Agent 作战台只读；基本信息、材料、时间线、面试复盘分别用低强调的“编辑”进入当前页编辑态，并用保存/取消明确提交边界。
- 阶段推进默认提供下一阶段，同时允许通过“调整阶段”纠正或跳过实际不存在的流程；每一次阶段变化均新增时间线事件。
- JD 术语是本地可解释的文本辅助，展示为“JD 命中的术语（可编辑）”，按职责、要求、加分项排序；不宣称为语义模型结论。

## 数据模型与兼容迁移

`JobStage` 使用十个阶段。`Job` 新增 `note: string`。旧数据在 `loadJobs()` 中先迁移、后校验：

| 旧值 | 新值 |
| --- | --- |
| `interested` | `to_apply` |
| `to_apply` | `to_apply` |
| `applied` | `applied` |
| `written_test` | `written_test` |
| `interviewing` | `first_interview` |
| `offer` | `offer` |
| `rejected` | `rejected` |

迁移同样作用于时间线阶段；缺失的 `note` 补为空字符串。首次需要改写旧数组前，把原始 JSON 存入一次性 `jobfind.jobs.backup.v3`。未知或不完整数据不得触发删除整个 `jobfind.jobs` 键；读取失败保持原始值、返回 `null`，让已有内存/默认状态继续工作并保留恢复机会。

## Store 边界

Store 提供受限更新方法，而非允许组件覆盖完整岗位对象：

- 基本信息更新只接收可编辑字段，并在阶段发生变化时追加事件。
- 材料更新同步岗位的 `boundMaterialIds` 和材料的 `boundJobIds`。
- 时间线与面试复盘按条目索引更新或删除，删除需由 UI 先确认。
- 所有成功写入更新 `updatedAt`；不改动 `id`、`createdAt`、Agent 输出的持久字段或未编辑区的数据。

## 规则变更

- 截止日期风险适用于待投递、已投递。
- 测评、笔试使用现有测试/跟进逻辑；一面、二面、三面、HR面均触发面试准备规则。
- 漏斗、统计、复盘和 Agent 文案共用阶段标签表，不能保留旧的“关注中/面试中”硬编码。

## 验收与回归

1. 旧岗位快照迁移后，数量、ID、JD、材料、关键日期、时间线与复盘均仍存在；仅阶段按映射改变，并存在原始备份。
2. 十列看板、阶段推进、阶段纠正、终态删除、风险/任务/统计均正常。
3. 看板卡片只含关键时间、Agent 风险、备注，备注限制 20 字并保存后立即显示；新建流程可填写并复核备注，公司与岗位名同级可扫读。
4. 四个非 Agent 页可完成编辑、取消、保存；材料关联保持双向一致。
5. 单测、类型检查、lint、静态构建、浏览器主流程和生产域名回归通过。
