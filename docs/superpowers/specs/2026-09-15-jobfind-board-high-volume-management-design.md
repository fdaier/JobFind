# JobFind 高容量申请看板设计

> 状态：已发布
> 日期：2026-09-15

## 目标

让批量投递后积累的大量岗位保持完整可见，同时让用户能快速定位特定公司／岗位，并将应处理事项从普通历史记录中区分出来。

## 已确认的产品决策

- **保留自然页面滚动。** 不做列内独立滚动、不固定列头、不将看板切成多个局部视口。
- 在看板顶部添加本地即时搜索、快捷筛选和排序；它们均是派生视图，不修改 localStorage。
- 搜索范围为公司、岗位名称、备注；过滤后继续显示十个阶段，并显示“匹配数／总数”。
- 快捷筛选为“全部”“需要处理”“有关键时间”。“需要处理”由现有 Agent 风险或 72 小时内／已过期的关键时间判断；“有关键时间”使用既有四类时间字段。
- 阶段内默认按“优先处理”排序：风险优先级、临近时间、最近更新时间。可切换“最近更新”“公司名”。
- 卡片重排为紧凑布局，但不删除既有的关键时间、Agent 风险或已填写备注。卡片内不再重复展示阶段徽标；阶段由所在列说明。空备注不占据版面，详情仍可查看和编辑。

## 信息与交互设计

### 控制条

控制条位于看板上方、横向滚动容器之外：

- 搜索框占主要空间，带搜索图标、清除按钮及 `/` / `Esc` 键盘行为。
- 三个筛选选项使用紧凑的单选分段控件，激活态只使用现有深色主色。
- 排序使用小型下拉菜单，默认“优先处理”。
- 任何非默认筛选都在控件内可见；搜索无结果时，十列仍保留并显示“无匹配岗位”，不让用户误以为数据消失。

### 阶段列与卡片

- 列头计数在默认态显示总数，在搜索／筛选态显示 `匹配数 / 总数`。
- 卡片的第一行承载公司与岗位；第二行承载关键时间；第三行承载 Agent 风险；有备注时追加一行单行备注。
- 风险为零时仍显示低强调“暂无风险”，保持用户此前约定的三类预览信息完整。
- 看板整体继续随页面滚动，横向十列结构不变。

## 数据保护

- 不新增或变更 `Job` 持久化字段，不迁移、不删除、不覆写既有岗位。
- 风险、时间、排序和匹配全部在客户端基于当前 store 数据重新计算。
- 原有卡片点击、详情编辑、阶段推进、删除、材料同步和 Agent 规则保持不变。

## 验收标准

1. 输入公司、岗位或备注可在一次输入后只显示匹配卡片，且每列清楚展示匹配数／总数。
2. “需要处理”正确显示有 Agent 风险或 72 小时内／已过期关键时间的岗位；“有关键时间”只显示存在时间字段的岗位。
3. 默认排序把高风险／紧迫岗位置前；另外两种排序结果可预期且不改变数据。
4. 卡片仍在不开详情时展示关键时间、Agent 风险与已填写备注，且不重复显示阶段标签。
5. 页面保持自然滚动；没有新增列内滚动或固定列头。
6. 现有岗位和旧 localStorage 数据的持久化内容不受影响。
