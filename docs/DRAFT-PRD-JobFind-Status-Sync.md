# DRAFT — JobFind 职位状态同步与状态收件箱

> 状态：已由 `docs/superpowers/specs/2026-09-30-jobfind-163-mail-status-inbox-design.md` 取代；保留为早期讨论记录。
> 日期：2026-09-30

## 用户问题

投递后的结果分散在官网、招聘平台、测评平台、邮件和短信中。用户不知道某岗位是否有新进展，只能逐个登录回查；而“无新状态”与“岗位已被淘汰但没有留意到通知”又很难区分。

目标不是代替用户投递或绕过招聘平台，而是让 JobFind 成为**状态变化的统一入口**：发现、匹配、提示、由用户确认。

## 方案选择

### 不作为第一版：全自动官网爬虫

不让 JobFind 保存官网密码或批量登录网站并轮询状态。不同公司官网和平台的登录、验证码、DOM、更新方式与规则差异很大；即使技术上能运行，也会频繁失效并带来账号安全和误判风险。

### 推荐主路径：邮件状态收件箱

招聘结果通常会先以邮件形式到达。接入用户明确授权的邮箱后，系统只读取求职相关邮件，将其转为“状态建议”，而不是直接改写申请阶段。

1. 用户主动连接 Gmail 或 Outlook，授予最小只读权限；其他邮箱可先通过规则转发到用户专属收件地址接入。
2. 系统只处理符合受控招聘来源、主题和内容模式的邮件，例如测评、笔试、面试邀约、录用、感谢信／不通过通知。
3. 使用公司别名、岗位名称、投递时间、发件域名和邮件内容共同匹配岗位，给出高／中／低置信度。
4. 在 JobFind 增加“状态收件箱”：展示来源、时间、邮件摘要、建议的新阶段、置信度与“确认更新／保留当前状态／忽略”。
5. **任何终态（录用、已淘汰）和模糊匹配都必须由用户确认。** 这避免同公司多岗位、营销邮件或历史邮件误改看板。

Gmail API 支持经用户授权访问邮箱，也提供邮箱变化的服务器端通知机制；这意味着真正的自动同步需要安全的服务端、OAuth 与令牌存储，而不是当前纯 localStorage 静态站点能独立完成的功能。参考：[Gmail API overview](https://developers.google.com/workspace/gmail/api/guides)。

### 辅助路径：官网页面一键识别扩展

为少数“只在官网更新、没有邮件”的情况提供 Chrome 扩展：

- 用户已经登录官网并打开“我的申请”页面时，点击扩展的“识别此页状态”。
- 扩展仅在用户当次授权的标签页读取可见 DOM、识别公司／岗位／状态／页面链接，并发送到 JobFind 的状态收件箱等待确认。
- 每个招聘平台采用独立适配器；没有适配器时只允许用户手动选中文本导入，不猜测状态。

Chrome 内容脚本可在获准页面读取 DOM，并通过扩展消息与后台部分通信；它需要明确的站点权限，因此该能力应以用户触发、逐站授权为准。参考：[Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。

## 产品结构

### 新增入口

- 看板控制条新增低强调“状态收件箱”，有待确认建议时显示数量。
- 岗位详情的“基本信息”新增“申请官网入口”（用户粘贴）与“最后确认状态”时间；这是官网扩展识别后的回跳依据，不要求每个岗位填写。

### 状态建议卡

每条建议包含：

- 匹配岗位：公司、岗位、当前阶段。
- 检测结果：例如“测评邀请”“笔试通知”“一面邀约”“录用通知”“不通过通知”。
- 来源和证据：邮件发件人／主题／收件时间，或官网域名／页面链接／抓取时间；只显示必要摘要，不默认保存完整邮件正文。
- 置信度与原因：例如“公司别名 + 岗位名完全匹配”。
- 用户操作：确认更新、保留当前阶段、忽略并学习为不匹配。

确认后才调用现有阶段推进逻辑并写入时间线，例如“由状态收件箱确认：笔试通知”。

## 分期实施

| 阶段 | 能力 | 基础设施 | 结果 |
| --- | --- | --- | --- |
| 0 | 岗位详情保存官网入口、最后确认状态；手动粘贴通知文本生成建议 | 现有本地应用 | 先验证匹配与确认体验 |
| 1（推荐） | Gmail／Outlook 只读 OAuth、状态收件箱、通知 | 账号、数据库、加密令牌、服务端 webhook／定时任务 | 自动收到主要求职邮件 |
| 2 | Chrome 扩展的“识别当前官网页” | 扩展、逐站权限、JobFind 同步 API | 补足无邮件的网站状态 |

## 数据与安全边界

- 当前项目必须从纯 localStorage 升级为带账号的后端后，才可做自动邮件同步；不在浏览器 localStorage 保存 OAuth token、邮箱密码或完整邮件。
- 默认最小权限、可随时断开、可删除同步数据；只保留状态匹配所需的最小摘要和来源元数据。
- 不自动发送邮件、不自动登录招聘网站、不绕过验证码、不批量抓取官网。
- 任何状态变更需保留来源和用户确认记录；终态永不静默自动更新。

## 成功标准

1. 用户无需反复打开官网，即可在状态收件箱看到主要招聘邮件对应的岗位与建议状态。
2. 用户在一条建议上一次确认即可更新看板和时间线；错误建议可忽略且不影响原岗位。
3. 同公司多岗位时，没有充分匹配证据的邮件不会自动绑定或改变阶段。
4. 用户能随时断开邮箱、删除同步数据，并清楚知道每一条状态来自哪里。

## 需要确认的决策

1. 你最常用、最希望优先接入的通知来源是 Gmail、Outlook，还是 QQ／163 等国内邮箱？
2. 是否同意引入账号与后端，以实现真正的自动邮箱同步？这是从“本机工具”升级为“有外部数据权限的服务”的必要前提。
3. 第一版是否接受“自动发现 + 你一键确认”，而不是自动静默修改岗位阶段？
